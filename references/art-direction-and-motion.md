# 構圖、動作與視覺完成度

用於新片、重做視覺，或「像簡報／只有過場／動畫不夠好」的回饋。若只要求更換配樂或局部修改，不擅自重做畫面。

## 先形成能執行的視覺提案

在專案的製作筆記留下簡短 treatment：觀眾要記住什麼、主要圖形是什麼、如何改變、最重要的落點、結束時留下什麼。將「高級、震撼、科技感」改寫為構圖與動作選擇；風格方向見 [style-recipes.md](style-recipes.md)。

用少量代表畫面檢查開場、資訊最密的一幕、主視覺與收尾。每張先看縮圖的焦點和明暗，再看全尺寸的字型、邊界與細節。若遮住文字後所有鏡頭都只剩同樣的框與線，重新設計主要圖形。簡潔可以是選擇，不能只是缺少設計。

先完成一段能呈現關鍵技法的短動態測試，再擴展到全片。測試應包含一次完整動作及其前後銜接；不要用十張靜態封面宣稱動作品質已過關。既有影片的局部修改可直接測受影響段落，不強制另做提案或等待批准。

## 構圖的取捨

- 明確分配主要圖形、標題與輔助資訊的優先順序。讓主要圖形有足夠面積，次要裝飾降低對比；不要每個框、線、字都同樣亮。
- 運用大小、實心／線條、疏密、正負空間及前後遮擋形成層級。不是每個鏡頭都要變色或加漸層；字排與留白本身要成立。
- 使用者喜歡固定日曆或雙欄版面時，保留錨點，在內容區改變圖形的尺度、排列、遮擋與因果動作。保留版面不代表所有事件都要用同樣三個方框。
- 長文先縮寫或分層呈現，不讓自動縮字將關鍵內容壓成註腳。中文標點、英文／數字字重與行距需在實際尺寸檢查。
- 數據圖的大小和比例需忠於資料；裝飾性長短或隨機數列不能冒充實測值。品牌標誌不做破壞比例的形變。

## 用事件因果編排動作

先寫每個主要動作的狀態變化，再寫座標。常用結構是「預備 → 施力／移動 → 接觸／轉變 → 餘勢 → 穩定」，不是每個元素套同一個淡入。

| 層次 | 設計決定 | 如何確認 |
| --- | --- | --- |
| 預備 | 主體在移動前略退、聚合或改變重心，提醒視線 | 預備仍看得清，不拖慢資訊閱讀 |
| 主動作 | 指定軌跡、速度曲線、接觸點與變化原因 | 中間影格可解讀；不是瞬移到下一狀態 |
| 次動作 | 跟隨主體錯峰、延後回彈或揭露結果 | 主次分明，沒有全部元素同時爭奪注意力 |
| 銜接 | 保留物體、位置、形狀或運動方向中的一個關係 | 能看出上一幕如何帶出下一幕 |
| 收束 | 動作停止後留下可閱讀的完整狀態 | 沒有半條線、未落定數字或額外閃動 |

以 30fps 為例，預備可從 3–6 幀、次元素錯峰可從 2–4 幀、落點後穩定可從 6–12 幀試起。這些是微調起點，不是所有動作的固定長度；莊重新聞不應照搬卡通彈跳。維持一個主要視覺動作，背景只在需要時提供低強度延續。

位移與縮放不要只有均速或同一條 ease-out。可用成熟動畫庫的 easing／spring／timeline，或既有管線的插值函式。對需要停止的 spring／物理模擬，預先解算或明確收斂；讀取任意 t 必須能重現同一狀態。

## 轉場與技術路線

讓有意義的物體帶出轉場：資料包移動到下一個節點、日期標記變成事件定位、圖表的一段成為下一幕的容器。硬切也可用於清楚的編輯分段；不要為了「連續」而虛構事件之間的因果。

形變要檢查輪廓對應、洞與筆畫的拓樸；必要時經過簡單中間形，不能把無關頂點直接插值而自交。可優先使用現成的 path morph 或向量工具。圖形、文字與鏡頭分層：高速移動的圖形可用適量 motion blur，重要文字及最終數字保持清晰。跨硬切的模糊取樣不得混入另一鏡頭。

| 視覺需求 | 可採路線 | 選擇限制 |
| --- | --- | --- |
| 精準 2D 圖形、資料敘事 | 既有 Skia、SVG／Canvas | 不因方便而只做線框；沿用成熟繪圖與字型工具 |
| 複雜向量形變、字排與遮罩 | SVG + 可用的動畫／形變套件 | 確認套件版本及授權，避免手刻完整引擎 |
| 等軸世界、真實空間與鏡頭 | Three.js 或 Blender | 用幾何、相機、光線支撐空間感；多個 2D 投影盒子不等於完整場景 |
| 材質、折射、液態、照明主導 | WebGL shader、Three.js、Blender | 只有風格需要時才增加成本；不要全片堆 bloom |

保留純時間介面，例如 `render(t)` 或 `window.renderAt(t)`，固定亂數種子、載入完字型及素材再渲染。要切換管線時先做短片驗證工具能力，不為了使用某個框架重做已成立的作品。現有 Python starter 仍可用；工具名稱本身不保證質感。

## 加速與片尾要一起設計

逐步加速時，分開控制事件停留、動作速度與音樂速度；短鏡頭應縮減次動作而非壓縮所有文字閱讀。非固定 BPM 必須共用速度表／beat-to-time 映射，不能還以固定 `t / beat_seconds` 驅動畫面。

先安排最後一次視覺完成、音樂終止起音、尾音區間及最終畫面，再分配前段時間。若採明確終止，最後重拍之後不得意外接回 hi-hat、低音 ostinato 或循環粒子。若刻意開放式結尾，則交代其連續或循環用途。不要用總音量淡出替代未完成的樂句。

停格前逐項確認入場線條、進度條、數字和圖形已完成；只凍結全局時間可能把半個動作永久留住。需要穩定構圖時，為動作設計明確終態。淡黑、定格或保留微動依影片選擇，CTA 仍為可選。

## 視覺評審與停止條件

技術 QC 之外，檢查縮圖／全尺寸關鍵影格、最快動作與轉場附近的連續影格，以及含完整收尾的短片。有播放或聽音能力才宣稱看過完整運動或試聽；連續影格與程式檢查的限制須如實說明。

以「時間碼 → 可觀察問題 → 對理解或觀感的影響 → 修改 → 修改後證據」記錄少量最高影響問題。優先修正主體太小、構圖單調、注意力競爭、運動無落點與結尾未完成，再修裝飾。用同內容、同時長的片段檢查改善，保留使用者已肯定的部分。

每次修改後針對受影響鏡頭驗證，再做必要的全片檢查。核心問題解決後交付，不為追求自行宣稱的「9 分／得獎級」無限迭代，也不能把自評分數當成品質證明。獨立評審可在已有授權及可用工具時採用；技能不因參考專案使用多代理就強制建立代理或其他聊天。
